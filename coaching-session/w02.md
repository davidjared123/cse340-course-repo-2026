```javascript
const getAllProjects = async () => {
    const query = `
        SELECT 
            p.project_id,

```

In this code, you defined the function using `async` and used `await db.query(query)`. Why is it necessary for database access functions to be asynchronous in Node.js?

**Student (David):** I think it is necessary because if it hasn't received a response from the database request, it would throw a null or not found error. Therefore, it needs to be asynchronous to say "first receive the information, and then display it," avoiding stack problems and errors.

**Coach:** Spot on, David! Because database requests travel over network sockets and take time to complete, executing them synchronously would freeze the single-threaded Node.js event loop. Using `await` cleanly pauses execution inside the function until the promise resolves with actual data rows, preventing the server from trying to read `undefined` or `null` variables without blocking the server from serving other concurrent requests.

### Topic 4: Client-Side Rendering (EJS Templates)

**Coach:** Finally, let's cover **Topic 4: Client-Side Rendering (EJS Templates)**.  
Here is how you display the projects in `src/views/projects.ejs`:

```html
<% projects.forEach(project => { %>
    <li>
        <%= new Date(project.date).toLocaleDateString('en-US', { year: 'numeric', month: 'short', day: 'numeric', timeZone: 'UTC' }) %>: 
        <strong><%= project.title %></strong> (<%= project.organization_name %>)
    </li>
<% }); %>
```

Notice that you used two different tag styles: `<% ... %>` (without the equals sign) around the `forEach` loop, and `<%= ... %>` (with the equals sign) around the title and date. What is the difference between these two EJS tags, and when should each be used?

**Student (David):** Continue.

**Coach:** Here is the key distinction:
1. `<% ... %>` (Scriptlet tag): Used strictly for JavaScript control flow (loops like `forEach`, conditional statements `if/else`). It executes the embedded code on the server during rendering without outputting any text directly into the final HTML document.
2. `<%= ... %>` (Escaped output tag): Evaluates the JavaScript expression, converts the result into text, and inserts it into the HTML document. Crucially, it **escapes** HTML characters (such as `<`, `>`, `&`, `"`, `'`) to protect the web application against Cross-Site Scripting (XSS) attacks.
