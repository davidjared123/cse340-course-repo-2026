TOPIC 3: PROTECTED ACCESS MIDDLEWARE
--------------------------------------------------------------------------------

[AI Learning Coach]:
¡Muy bien pensado, David! Diste en el punto clave: como la web no tiene memoria entre peticiones (es stateless), la sesión en el servidor nos permite mantener identificado al usuario y conocer sus roles en todo momento.

Ahora avancemos al Tema 3: Middleware de Acceso Protegido (Protected Access Middleware).

En tu archivo src/controllers/users.js (L156-L171), implementaste la función `requireRole`:

```javascript
const requireRole = (role) => {
    return (req, res, next) => {
        if (!req.session || !req.session.user) {
            req.flash('error', 'You must be logged in to view that page.');
            return res.redirect('/login');
        }
        if (req.session.user.role_name !== role) {
            req.flash('error', 'You are not authorized to view that page.');
            return res.redirect('/dashboard');
        }
        next();
    };
};
```

¿Qué hace exactamente esta función al proteger una ruta, y por qué tuviste que diseñarla como una función que retorna otra función (factory function) en lugar de un middleware común y corriente?

[David De Gennaro]:
